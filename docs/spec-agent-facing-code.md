# 面向 Agent 的代码规范总纲

本 L4 文档由 [L3 设计](agent-facing-code-design.md)拥有。它只定义共同总纲；
G/N/L/V/O/D/P/C/X 分组的 67 条编号条款须由各分组证据独立完成。

## 1. 规范性定义

### 1.1 Agent 读代码的四条约束与对应条款轴

| 约束 | 事实形态 | 对代码的要求 | 对应组 |
| --- | --- | --- | --- |
| 读取有截断 | 多数 agent CLI 单次读取有行数上限（如默认 2000 行） | 文件必须小到可整读，或必须可分节取读 | L 局部性 |
| 注意力随上下文退化 | 检索质量早于宣称窗口下滑，窗口内还挤着提示词、历史、工具输出 | 定位必须靠检索而非通读，名字必须唯一可检索 | N 可导航性 |
| 检索比整读便宜 | 检索是 agent 的主要导航方式 | 路径、名字、常量、入口必须可被检索命中 | N、D |
| 每次动作都计费 | 每次工具调用消耗 token 与时间 | 验证必须一条命令完成，输出必须精简可解析 | V 可验证性、O 可观测 |

### 1.2 三档阈值

| 档 | 含义 | 超限处置 |
| --- | --- | --- |
| 红线 | 超过即判不符合，必须有机器判定 | 阻断合并，或进入豁免登记并注明到期日 |
| 默认 | 本仓多数文件的正常落点 | 超限须写明理由，不阻断合并 |
| 建议 | 取向性，不作判定 | 只记录 |

“超过”是严格大于：等于阈值通过。未完成本仓标定的“本规范设定”数值不得作为符合性判定，
只能按建议档记录。

### 1.3 三类取证方式

- 机器可查：存在脚本、linter 规则或 CI 任务，可在本地复现同一结论。
- 人核：靠抽查清单与判断，必须写明抽查比例与记录位置。
- 只作取向：无法判定，条款只表达意图，不得用于合规结论。

## 2. 阈值与来源

下表只列需要数字的条款。性质标“引用”的值来自公开建议或事实；“对照”来自与本机已有件
比对；“本规范设定”的值必须按本仓重新标定后才生效。机器使用的结构化表示是
[`config/agent_code_thresholds.yml`](../config/agent_code_thresholds.yml)，当前取证和偏差见
[36 单元审计](agent-facing-code-audit.md)。

| 项 | 红线 | 默认 | 性质与来源 |
| --- | --- | --- | --- |
| 单文件行数 | 2000 行 | 500 行 | 引用：2000 行取自“agent CLI 单次读取默认上限 2000 行”这一事实形态（AkitaOnRails，2026-04-20）；500 行为该文模板的建议值，属建议非实测 |
| 单函数行数 | 40 行 | 20 行 | 引用＋本规范设定：来源建议区间为 4 至 20 行，上限 40 行为本规范设定 |
| 嵌套深度 | 4 层 | 2 层 | 引用＋本规范设定：默认 2 层来自来源模板建议，红线为本规范设定 |
| 同名标识符出现次数 | 5 处 | 1 处 | 引用：来源建议名字的检索命中数小于 5，本规范把“默认”定为唯一 |
| 常驻规则文件行数 | 50 行 | 32 行 | 对照＋本规范设定：对照同体裁规则包的常驻档位为 47 行与 32 行，本规范把上限设为 50 行 |
| 全量门禁时长 | 10 分钟 | 5 分钟 | 本规范设定 |
| 单次变更规模 | 需按仓标定 | 需按仓标定 | 本规范设定：本仓标定前不作判定，只记录 |

门禁时长与变更规模若本仓已有先例（例如基线检查脚本的实际耗时），以本仓实测覆盖本表
数值，并在阈值文件中记录覆盖日期。

## 3. 符合性等级

- 完全符合：第二章全部“必须”与“不得”条款满足；“应当”条款的偏离均有书面理由。
- 部分符合：G、N、V 三组的强制条款全部满足；L、O、D、P、C、X 组存在未满足项，且已列出补齐计划与时间点。
- 起步阶段：G 组全部满足，N 与 V 两组在建：条款已归位，检查器尚未全部落地。
- 不符合：G、N、V 三组存在强制条款未满足且无计划。此状态下不得声称代码已面向 agent。

本票没有完成九组 67 条的证据，因此不填写任何仓库级“完全符合”“部分符合”或“起步阶段”
正向声明。
