# Documentation Alignment Matrix

This matrix records claim-level ownership: each long-lived topic has exactly one owning
document (single source of truth); other documents link instead of restating. It is the review
checklist for keeping product direction, architecture, and operator docs
consistent. `mix docs.check` enforces document structure; this matrix tracks claim ownership.

| Worker execution modes | `README.md`, `ARCHITECTURE.md`, `docs/persistence_and_auth.md`, `docs/worker-panel-decoupling-design.md` | Default execution is centralized. A successful worker claim creates the run, applies the `AgentRunner.Policy` profile-derived started state (`Todo -> Refining` for refinement, `Ready -> In Progress` for implementation), returns the assignment/payload at that started state, and feeds that live run into the orchestrator current-state snapshot; terminal, cancellation, expiry, or stale-run reconciliation removes it. History duplicate gating treats `Refining` and `In Progress` as worker started states and allows redispatch only after the latest worker run is terminal. Advertised aggregate slots are observability; effective admission is 0/1. Worker heartbeat freshness persistence is coalesced by `Worker.HeartbeatHistory` outside the heartbeat HTTP response path; delayed or failed history writes do not change status, retry headers, heartbeat-failure metrics, queued work, assignments, failed runs, or repair actions. Idle no-lease heartbeats do not enter the manager, and matching active-lease renewal uses only a bounded manager critical section. Retryable active-lease renewal timeout/overload returns 503 and increments memory-backed current-state metrics without creating queued work, assignments, failed runs, or repair actions. Zombie reconciliation does not expire worker sessions or use DB heartbeat freshness as a recovery precondition; after Panel restart an unknown worker session is held by the run-level lease window before a stale `In Progress` issue can return to `Ready`. Worker claim payloads use the profile-derived started state, so refinement payloads operate from `Refining -> Needs Refinement Review` while implementation payloads keep `In Progress -> Ready to Merge`; duplicate-run gating treats `Refining` and `In Progress` as worker started states. Successful empty claims use bounded 5/30/60-second idle advice; tracker or exhausted worker HTTP failures use bounded 30/60-second backoff and reset only after a successful tracker/claim response. Active-lease renewal timeout/overload is a retryable 503 with `worker_heartbeat_unavailable`, `retry_after_seconds`, and `Retry-After`; a later successful heartbeat still renews only the current matching assignment. When the environment failure circuit is open, worker claims return empty before tracker candidate reads. Worker restricted-tool audits travel as correlated, non-terminal task events for Panel persistence; delivery failure is observable but does not alter tool or assignment outcomes. Expiry ends the run, and run-lease reconciliation may return a stale `In Progress` issue to `Ready` without treating session heartbeat age or offline status as recovery authority, but no persisted task is restored or requeued. |

## Documentation Update Requirements

When implementation changes product behavior, update the docs in the same change:

- Runtime/config behavior: `README.md`, `docs/user-guide.zh-CN.md`, `docs/persistence_and_auth.md`, `docs/long_term_direction.zh-CN.md`.
- Settings behavior: `docs/user-guide.zh-CN.md` and this matrix.
- Worker/deployment behavior: `README.md`, `ARCHITECTURE.md`, `docs/worker-panel-decoupling-design.md`, and deployment docs.
- Post-handoff review behavior or deployment topology: `docs/pr-review-design.md`, its linked L4 contract owner, and this matrix.
- Observability behavior: `README.md`, `ARCHITECTURE.md`, `docs/long_term_direction.zh-CN.md`, and run/events docs when present.
- Public repository positioning: root `README.md`.

Future intent belongs in an L3 design with an explicit status. Current behavior belongs in its
canonical owner and should link to reviewable implementation where delivery evidence is useful.
