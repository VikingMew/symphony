# 233 Merge agent-runner issue/operator lifecycle

## Goal

Remove the duplicated workspace/hook/session lifecycle between normal issues and operator tasks; one shared path with kind-specific callbacks.

## Status

Completed.

## Background

Source: Codex static-analysis report (codex-cli 0.147.0, read-only; 20 findings across
lib/). This plan addresses: Redundancy [1] (medium): agent_runner.ex:77-125,222-280,404-461; identifier dup at agent_runner.ex:514-526 vs orchestrator.ex:1875-1887.

`run_on_worker_host/4` and `run_operator_on_worker_host/5` are near-identical: workspace creation, runtime info, before/after hooks, session start, phase events, try/after stop_session. The operator identifier algorithm is copied in agent_runner and orchestrator. Two lifecycle implementations means two places to fix bugs and two ways to drift.

## Scope

- Extract shared `with_workspace/2`, `with_codex_session/2` (or equivalent) used by both paths; differences expressed via callbacks or an explicit run-kind.
- Single `OperatorTask` identity builder (identifier/label/description) used by both agent_runner and orchestrator.
- Behavior must stay equivalent (same hooks, same phase events, same error handling per path).

## Out of Scope

- Changing hook semantics; run-history format changes.

## Acceptance Criteria

- Both paths run through the shared lifecycle (verified by existing tests for issue runs and operator runs).
- Operator identifiers generated by ONE function; orchestrator delegates to it.
- No behavior change in hook order/phase events (tests pin these).

## Test Cases

- Full core_test + app_server_test + operator run tests (nap/day_dreaming paths).
- Identifier unit tests: same input => same identifier from both old call sites' contract.

## Implementation Notes

Biggest mechanical risk is subtle hook-order drift; run the operator E2E-ish tests and diff the phase event sequences.

## Completion Deviations

- Extracted `with_workspace/5` (workspace create + before/after hooks + phase events + try/after)
  shared by `run_on_worker_host/4` and `run_operator_on_worker_host/5`; and `with_codex_session/6`
  (rate-limit gate -> prepare callback -> AppServer.start_session -> phase events -> try/after
  stop_session) shared by `run_profile/...` and `run_operator_codex_turn/...`. Path differences are
  expressed via `prepare` (issue: `{:ok, nil}`; operator: profile policy) and `run` callbacks.
  Hook order and phase event sequence are byte-identical to the pre-merge implementations.
- New public API `AgentRunner.operator_task_identity/2` (kind, run_id) -> %{identifier, label,
  description}; orchestrator's `operator_running_entry/4` and `operator_task_issue/1` delegate to
  it, and the duplicated `operator_task_identifier/2` + `operator_task_label/2` clauses were
  deleted. `operator_task_label/1` remains as a thin delegate to `identity(kind, nil).label`.
- Deviation: the old orchestrator `operator_task_label/1` had a `to_string(kind)` fallback clause
  for unknown kinds; the new delegate goes through `operator_task_identity/2` which only matches
  `:nap | :day_dreaming` (FunctionClauseError for any other kind). The operator kind set is closed
  and type-annotated (`operator_kind :: :nap | :day_dreaming`), so no production path is affected.
- New tests: agent_runner_test.exs canonical-identity unit test; orchestrator_operator_tasks_test
  asserts running-entry identifier/label == `AgentRunner.operator_task_identity/2` output.
